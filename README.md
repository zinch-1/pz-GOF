# Реалізація GOF Патернів Проєктування на TypeScript

## Як запустити проєкт

1. Встановіть залежності: `npm install`
2. Запустіть демонстраційний сценарій: `npm start`

## Опис реалізованих патернів

### Породжувальні патерни (Creational)
1. **Prototype (Прототип)**
  * **Призначення:** Копіювання об'єктів без прив'язки до їхніх класів.
  * **Покращення:** Дозволяє легко створювати складні об'єкти на базі існуючих (наприклад, генерація ворогів у грі), зберігаючи інкапсуляцію приватних властивостей.
2. **Singleton (Одинак - на прикладі Логера)**
  * **Призначення:** Гарантує існування єдиного екземпляра класу в усій програмі.
  * **Покращення:** Усуває конфлікти запису в єдиний ресурс (файл або масив логів) між різними модулями системи.

### Структурні патерни (Structural)
3. **Bridge (Міст)**
  * **Призначення:** Розділення абстракції (пульти управління) від реалізації (пристрої).
  * **Покращення:** Запобігає "вибуху" ієрархії спадкування. Замість $N \times M$ класів (де N — типи пультів, M — типи пристроїв), ми маємо лише $N + M$ класів.
4. **Composite (Компонувальник)**
  * **Призначення:** Дозволяє будувати деревоподібні структури і працювати з гілками та листками через єдиний інтерфейс.
  * **Покращення:** Клієнту не потрібно знати, чи обробляє він один файл, чи цілу папку з тисячею вкладень — метод `getSize()` працюватиме ідентично завдяки рекурсії.

### Поведінкові патерни (Behavioral)
5. **Chain of Responsibility (Ланцюжок обов'язків)**
  * **Призначення:** Передача запиту послідовно через ланцюг обробників (Middleware).
  * **Покращення:** Дозволяє динамічно формувати послідовність перевірок (авторизація -> валідація -> кеш) і тримати кожен обробник в окремому класі (принцип Single Responsibility).
6. **Template Method (Шаблонний метод)**
  * **Призначення:** Визначення каркасу алгоритму з делегуванням деталей підкласам.
  * **Покращення:** Усуває дублювання коду в споріднених класах. Вся спільна логіка винесена в базовий клас, а унікальна залишається в дочірніх.
